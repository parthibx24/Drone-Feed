## Overview

```
C12 ─► Pi go2rtc ─► 4G ─► central go2rtc ─┬─► browsers (video)
                                           └─► detector (RTSP on localhost, ~3 frames/s)
                                                  │ boxes + new-object events (HTTP, token)
                                                  ▼
                                               gateway ─► UI over the existing WebSocket
                                                  ├─ event log + snapshots (recordings volume)
                                                  ├─ alerts (Telegram, webhook)
                                                  ├─ auto-record
                                                  ├─ "Analyze frame" (Claude vision)
                                                  └─ follow (gimbal rate commands)
```

- **Detection runs on the server, not the drone.** star9's Pi Zero 2 W cannot decode the H.265 video, let alone run a model.
- **The detector only pulls video when it is useful:** while a drone is armed, or while someone has its dashboard open. The detector reads the stream from the central go2rtc, which is already pulling it for viewers. When nobody watches and the drone is on the ground, no video crosses the 4G link because of AI.
- **Two models**, chosen by stream name (`*_thermal` → thermal):

| Stream | Model | Trained on | Classes |
|---|---|---|---|
| Visible | YOLO11n "AeroEdge" | VisDrone (drone footage) + DOTA | person, car, truck, bus, van, bicycle/motorbike, boat, aircraft |
| Thermal | YOLO11n, trained here | HIT-UAV (drone thermal footage, 60–130 m) | person, car, bicycle, other vehicle |

  Labels are normalised to `person`, `car`, `van`, `truck`, `bus`, `bike`, `boat`, `aircraft`, `vehicle`, and grouped as `person`, `vehicle` or `other`.

- **Licences.** Both models are Ultralytics YOLO11 derivatives (AGPL-3.0). VisDrone and DOTA are for academic use; HIT-UAV is CC-BY-4.0. For a commercial deployment, either release the detector's source under AGPL or retrain a permissively licensed architecture on data you may use commercially. The detector accepts any Ultralytics-format ONNX model, so swapping the model needs no code change.

## Accuracy and cost (measured 2026-11-11)

**Thermal model**, on HIT-UAV's 579 held-out test images (never used in training), through the detector's own code ([`eval_thresholds.py`](../ai/training/eval_thresholds.py)), at the default threshold 0.35:

| Class | Labelled | Precision | Recall |
|---|---|---|---|
| Person | 2,611 | 0.88 | 0.88 |
| Car | 1,339 | 0.91 | 0.96 |
| Bike | 796 | 0.87 | 0.86 |
| Other vehicle | 34 | 0.81 | 0.74 |

Overall mAP50 0.883. Lowering `min_confidence` to 0.25 finds 2% more people for 4% more false boxes. A single detection is never an event: an object must be seen in 3 frames first, which removes most one-frame false boxes.

**Visible model:** published mAP50 0.569 at 640 px on VisDrone. On sample drone photos it finds most vehicles. People who are only a few pixels tall are often missed, because a 1280×720 frame is shrunk to 640 px. `TILES=2` also runs the model on the left and right halves at higher detail: on a dense 1920×1080 test frame it found 35 objects instead of 18, at about 3× the CPU.

**Not measured yet:** accuracy on the C12's own footage. HIT-UAV was filmed with a 640×512 thermal camera, while the C12's is 384×288; VisDrone was filmed in Chinese cities. Check both on real flights with `python -m detector file <recording> --kind ...`, and retrain with your own labelled footage if needed ([`train_thermal.py`](../ai/training/train_thermal.py) shows the steps).

**CPU per frame** (one core, Apple M4; the server's EPYC cores are similar): about 75 ms for the visible model, 25–40 ms for thermal. At 3 frames per second per camera that is about a third of one core for both cameras, plus video decoding.

## Features

| Feature | What it does | Needs |
|---|---|---|
| Live boxes and counts | Boxes over the video; people and vehicle counts per camera | Detector |
| Event log | One event per newly confirmed object (seen in 3 frames), with a snapshot, the drone's position, and an estimated ground position | Detector |
| Map markers | Events from the last 30 minutes with a ground position appear on the dashboard map | Gimbal angle known (see below) |
| Alerts | Telegram message with the snapshot, and/or a webhook POST, for chosen labels; one per drone and label per cooldown | `ai.alerts` |
| Auto-record | Starts the drone's recording when a chosen label is detected; stops it after a quiet period. A recording started by hand is never stopped by AI. | `ai.auto_record` |
| Analyze frame | Sends the current frame and an optional question to Claude; the answer appears in the AI tab | `ai.vision.api_key` |
| Follow | Click a box: the gimbal keeps that object centred, using rate commands at 5 Hz. Stops when the track is lost for 2 s, when the operator moves the gimbal, or on Stop. | Operator, a gimbal |

### Ground position estimate

The C12 does not report its gimbal angle, so the gateway uses the **last commanded** absolute angle (Gimbal attitude, Center) plus the rate commands sent since. It assumes flat ground at the take-off height, and ignores the drone's roll and pitch and the lens distortion. The result is marked approximate, and is left out entirely until an absolute gimbal angle has been commanded since the gateway started, or when the camera looks less than 5° below the horizon. Field of view per camera comes from `ai.camera`.

## Configuration (`gateway.yaml`)

```yaml
ai:
  enabled: true
  ingest_token: ${AI_INGEST_TOKEN}   # shared with the detector container
  # data_dir: /recordings/.ai        # events.jsonl + snapshots/ (default: <recordings_dir>/.ai)
  retention_days: 30
  run_when: auto                     # auto (armed or watched) | always
  fps: 3
  min_confidence: 0.35
  camera:
    visible_hfov_deg: 62
    thermal_hfov_deg: 42
  alerts:
    labels: [person]
    cooldown_s: 120
    telegram: { bot_token: ${TELEGRAM_BOT_TOKEN}, chat_id: "-100123" }
    webhook_url: ""
  auto_record:
    labels: [person]
    stop_after_s: 30
  vision:
    api_key: ${ANTHROPIC_API_KEY}
    model: claude-opus-5-5
    effort: medium
  follow:
    max_rate_deg_s: 10
```

Every block except `enabled` and `ingest_token` is optional; leaving one out turns that feature off.

## Interface contract

### Detector → gateway

Authenticated with `Authorization: Bearer <ai.ingest_token>`. These endpoints accept nothing else, and the token is accepted nowhere else.

| Method | Path | Body / response |
|---|---|---|
| GET | `/api/v1/ai/targets` | → `{"targets": [{"drone_id", "stream", "kind": "visible"|"thermal"}], "fps", "min_confidence"}` |
| POST | `/api/v1/ai/detections` | a **DetectionFrame** → `{"ok": true}` |
| POST | `/api/v1/ai/events` | multipart: `event` (JSON: `drone_id`, `stream`, `kind`, `ts`, `track_id`, `label`, `group`, `confidence`, `box`) and `snapshot` (JPEG) → `{"ok": true, "id"}` |

**DetectionFrame:**

```json
{"drone_id": "kotowali", "stream": "Kotowali-Thana-SMP_camera", "kind": "visible",
 "ts": "2026-11-11T03:00:00.123Z", "width": 1280, "height": 720,
 "model": "aero-visible", "infer_ms": 42.1,
 "detections": [{"track_id": 7, "label": "person", "group": "person",
                 "confidence": 0.81, "box": [0.41, 0.52, 0.03, 0.07]}]}
```

`box` is `[x, y, w, h]`, normalised to 0–1, measured from the top-left corner.

### Gateway → UI

| Method | Path | Role | Notes |
|---|---|---|---|
| GET | `/api/v1/drones/{id}/ai` | V | **AIStatus** (below) |
| POST | `/api/v1/drones/{id}/ai` | O | `{"enabled": bool}`: AI on/off for this drone (runtime only, resets to on at restart) |
| POST | `/api/v1/drones/{id}/ai/analyze` | O | `{"stream"?, "prompt"?}` → `{"ok", "text", "stream", "model", "at"}`; 503 if not configured |
| POST | `/api/v1/drones/{id}/ai/follow` | O | `{"stream", "track_id"}` → `{"ok"}` |
| DELETE | `/api/v1/drones/{id}/ai/follow` | O | Stop following |
| GET | `/api/v1/ai/events` | V | Query: `drone`, `group`, `label`, `since`, `until` (RFC 3339), `limit` (default 200, max 1000) → `{"events": [AIEvent]}`, newest first |
| GET | `/api/v1/ai/events/{id}/snapshot` | V | JPEG |

**AIStatus:**

```json
{"enabled": true, "configured": true, "detector_online": true, "active": true,
 "last_frame_at": "…",
 "streams": {"Kotowali-Thana-SMP_camera": {"kind": "visible", "fps": 2.9, "infer_ms": 41,
              "counts": {"person": 3, "vehicle": 1, "other": 0}, "frame": {DetectionFrame}}},
 "follow": {"active": false, "stream": "", "track_id": 0},
 "features": {"analyze": true, "alerts": true, "auto_record": false, "follow": true}}
```

`active` means the detector is currently asked to process this drone (armed or watched).

**AIEvent:**

```json
{"id": "20261111T030000Z-kotowali-7", "drone_id": "kotowali", "drone_name": "Kotowali",
 "stream": "…_camera", "kind": "visible", "at": "…", "track_id": 7,
 "label": "person", "group": "person", "confidence": 0.81, "box": [0.41, 0.52, 0.03, 0.07],
 "drone": {"lat": 24.89, "lon": 91.87, "alt_rel_m": 60, "heading_deg": 47} | null,
 "geo": {"lat": 24.8902, "lon": 91.8711, "distance_m": 85, "approx": true} | null,
 "snapshot_url": "/api/v1/ai/events/<id>/snapshot", "alerted": false, "recording": false}
```

**WebSocket** (`/api/v1/drones/{id}/ws`), in addition to the existing types:

| `type` | `data` |
|---|---|
| `detections` | DetectionFrame (every processed frame) |
| `ai_event` | AIEvent |
| `ai_follow` | `{"active", "stream", "track_id", "reason"}` (`reason` set when following stops) |
